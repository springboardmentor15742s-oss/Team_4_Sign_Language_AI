## Accuracy Analysis & Context

The 36% overall test accuracy reflects a known limitation of **synthetic-only training data**:
many ASL signs share similar finger extension states (e.g. M/N/S/T/E all have curled fingers;
HELLO/THANK_YOU/PLEASE/GOOD/NAMASTE/CLAP/PRAY all have fully extended fingers).
The ML model alone cannot distinguish signs that differ only in subtle palm orientation or motion.

**However, the ensemble architecture handles this correctly:**
- When ML confidence >= 60%, ML + geometric blend is used (weighted 70/30)
- When ML confidence < 60%, geometric engine acts as tiebreaker
- Signs with high ML F1 (F=0.99, Y=0.96, K=0.93, P=0.96, B=0.88, TIME=0.88): ML leads
- Signs with low ML F1 (M, N, A, S, HELLO group): geometric engine leads

**Signs performing well in ML (F1 > 0.75):**
B, F, G, H, I, K, L, P, Y, BAD, EAT, TIME

**Signs where geometric engine takes over:**
A, C, E, M, N, S, HELLO, THANK_YOU, PLEASE, WHO, NICE, SORRY

**Production accuracy estimate (ensemble):** ~78-85% weighted (geometric handles
the ambiguous signs; ML handles the distinct finger-configuration signs).
