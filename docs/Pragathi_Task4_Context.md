# Pragathi Task 4 Context — Database Logging & Analytics

**From:** Chinmayee Badiger  
**Milestone:** 2  
**Purpose:** Give Pragathi the backend API response fields needed to write SQL for practice history, skill mastery, AI feedback, and quiz score updates.

## Backend Endpoint Ready

Chinmayee's backend API is available at:

```text
POST /api/ai/evaluate
```

It receives the sign selected by the learner and the 21 MediaPipe hand landmarks captured from the webcam.

## Request Body From Frontend

Preferred request shape:

```json
{
  "sign_name": "A",
  "landmarks": [
    { "x": 0.51, "y": 0.72, "z": 0.0 }
  ],
  "session_id": "practice-001",
  "source": "webcam"
}
```

Notes:

- `sign_name` is the target sign the learner is practicing.
- `expected_sign` is also supported for compatibility, but `sign_name` is preferred.
- `landmarks` should contain 21 `{x, y, z}` points from MediaPipe.
- `landmarks_flat` is also accepted as a 63-number vector.
- `session_id` can be generated by the frontend for grouping one practice attempt.

## Response Body For Database Logging

The endpoint returns:

```json
{
  "predicted_sign": "A",
  "accuracy_percentage": 92.5,
  "is_correct": true,
  "corrections": ["Hand angle optimal", "Good thumb position"]
}
```

## Fields Pragathi Should Use

| API field | Meaning | Suggested DB use |
| --- | --- | --- |
| `sign_name` | Target sign selected by learner | `Practice_History.sign_name` |
| `predicted_sign` | Model's predicted sign | `AI_Practice_Feedback.predicted_sign` |
| `accuracy_percentage` | Gesture score from 0 to 100 | `Practice_History.accuracy_score`, `Skill_Mastery.mastery_percentage` input |
| `is_correct` | Whether predicted sign matched target | `Practice_History.is_correct` or quiz result flag |
| `corrections` | List of coaching messages | Store as JSON/text in `AI_Practice_Feedback` |
| `duration_seconds` | Sent/calculated by practice UI, usually 10 seconds | `Practice_History.duration_seconds` |
| `learner_id` | Current logged-in learner from auth/session | Foreign key for all learner-specific rows |
| `session_id` | Practice/quiz attempt id from frontend | Optional grouping id for related feedback rows |

## Skill Mastery Update

After saving practice history, update the learner's mastery for that sign/module.

Suggested logic:

```text

status =
  "Mastered" if mastery >= 80
  "In Progress" if mastery >= 50 and < 80
  "Needs Practice" if mastery < 50
```

## Learner Profile Weighted Score

Use the project formula:

```text
overall_score = 0.40 * Ga + 0.25 * Ap + 0.15 * Lc + 0.10 * Pc + 0.10 * Si
```

Suggested meaning:

- `Ga` = gesture accuracy average
- `Ap` = assessment performance
- `Lc` = lesson completion
- `Pc` = practice consistency
- `Si` = skill improvement rate

For Milestone 2, `Ga` can come from practice history accuracy scores, and `Ap` can come from Speed Quiz scores.
